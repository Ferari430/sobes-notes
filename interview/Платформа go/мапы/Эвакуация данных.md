NOTE: Из-за эвокуации данных нельзя брать указатель на элемент мапы, потому что из-за эвокуации ключ-значение переезжает в другой бакет. 

Есть есть 4 бакета в каждом из которых лежит 7 ключ-значений.
ТОгда заполненность = 7значений*4бакета/4бакета = 7.
Эвокуация данных происходит при заполненности =  от 6,5

---
В мапу нельзя писать конкурентно без защиты мьютексом. Происходит паника.
	Представим что конкурентно пишем в мапу. Вдруг начинается эвокуация из старого бакета в новые. При этом найдется горутина которая все ещё пишет в старый бакет --> теряем данные.	
	
==При чем чтение из мапы можно проводить из многих горутин - это потокобезопасно.==

Эвокуация происходит так:
создаются новые бакеты (больше бакетов чем старое кол-во), берется старый бакет, из него достаются все элементы и по одному распределяются по новым бакетам 
![Pasted image 20251207000351](../../../attachments/Pasted%20image%2020251207000351.png)
По всей видимости тут пересчитывается хэш у ключ-значений, потому что они должны соответствовать новому бакету.
Пример:
```go
type User struct{}

func main() {
	m := make(map[User]int)

	u := User{}
	m[u] = 2

	fmt.Println(&m[u])

	fmt.Println(m[&u])
}
```

При fmt.Println(&m[u]) будет:
	./main.go:14:15: invalid operation: cannot take address of m[u] (map index expression of type int)
	==*Нельзя брать указатель от ключ-значения в мапе потому что данные могут эвокуироваться - переехать в другой бакет, что приведет к смене адреса памяти.*==


При fmt.Println(m[&u]) будет:
	./main.go:15:16: cannot use &u (value of type *User) as User value in map index
==Мапа в качестве ключа требует значение а не ссылку!==

Каждая эвокуация - дополнительные аллокации. Поэтому если мы знаем заранее количество данных то лучше создавать мапу определенного размера.
