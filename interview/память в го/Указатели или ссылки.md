Видео 2.2
Важно:
При передачи в функцию ссылки передается не сама  ссылка, а копия ссылки (Ссылка тоже копируется!).  
При виде конструкций типа 
```go
func changeName(name *string) {
p = &Person{
		name: name,
	}
}
```
важно понимать, что р это копия ссылки, и мы этой переменной присваиваем абсолютно новую ссылку, и будем работать уже со сторонним объектом, поэтому исходный объект изменен не будет.

Передача по ссылке или передача по значению:
В го все передается по значению (то есть идет копирование переданной переменной).

Тут передается и копируется строка 
```go
func changeName(name string) {
}
```
Тут передается и копируется ссылка на строку
```go  
func changeName(name *string) {
}
```

Пример:
```go
func main() {
name := "Bob"
log.Printf("[main] Value: %v, addres: %p \n", name, &name)
changeName(name)
}

func changeName(name string) {
log.Printf("[changeName] Value: %v, address: %p \n", name, &name)
}
```
Вывод:
2025/11/06 05:57:21 [main] Value: Bob, address: 0xc000014080 
2025/11/06 05:57:21 [changeName] Value: Bob, address: 0xc0000140b0 

Видим, что имя переданной переменной в функцию changeName одно и то же (Bob), но адреса разные.

func main() {
name := "Bob"
log.Printf("[main] Value: %v, addres: %p \n", name, &name)
changeName(&name)

func changeName(name *string) {
log.Printf("[changeName] Value: %v, address: %p \n", name, &name)

Вывод:
2025/11/06 05:57:21 [main] Value: Bob, address: 0xc000014080 
2025/11/06 05:57:21 [changeName] Value: 0xc000014080, address: 0xc000074048

Видим, что значение у переменной, переданной по ссылке, является сама ссылка на изначаьлный объект, адрес новый - для поинтера. 
Вывод: адреса разные, потому что даже передавая по ссылке -  сама ссылка копируется, да, она указывает на переданный объект, но сама ссылка создается и имеет другой адрес памяти.


---
Пример:
```go
func main() {
	name := "Bob"
	changeName(name)
	log.Println(name) // Bob
}

func changeName(name string) {
	name = "Alice"
}
```
Вывод:
"Bob"
Потому что передали копию значения name. Фунция отработала и затерлась в стэке.

Что если передадим по ссылке?
Пример:
```go
func main() {
	name := "Bob"
	changeName(&name)
	log.Println(name) // Bob
}

func changeName(name *string) {
	newName := "Alice"
	name = &newName // тут лежит указатель на новую переменную
}
```

Функция ждет ссылку, передаем. Заводим новую строку, присваиваем в name(ptr) новую ссылку на Alice. Но все равно имя не меняется.

Рассмотрим стэк фрэйм функции changeName. При ее вызове в стэк фрэйме создается локальная переменная name, ей присваивается новое значение, после того как функция отработала, стэк Фрэйм очищается и name перестает быть валидным для этой функции, в итоге оригинал не поменяли.

Все что можно сделать - совершить dereference:
Пример:
```go
func main() {
	name := "Bob"
	changeName(&name)
	log.Println(name) // Alice
}

func changeName(name *string) {
	*name = "Alice" // тут напрямую получаем доступ к переменной из main
}
```

dereference это разэменование. Означает что мы берем указатель на name, оператором * достаем из участка памяти значение Bob и меняем на Alice.

Вывод: нужно работать с переменной которая была создана не в стэк фрэйме функции которая меняет переменную. 

Задача с собеседования:
Берем и в функции через & делаем p указателем. По указателю меняем имя. Но имя не меняется! 
```go
type Person struct {
	name string
	age int
}

func (p *Person) changeName(name string) {
	p = &Person{
		name: name,
	}
}

func main() {
	p := Person{
		name: "Bob",
		age: 25,
		}
	p.changeName("Alice")
	log.Println(p.name) // Bob
}
```

Так не сработает. Сссылке в функции присваивается абсолютно новая ссылка. И поэтому меняем уже не первоначальный а сторонний объект.

Можно изменить через dereference но тогда будет создаваться новый Person и поле age сотрется (будет 0). Поэтому лучший способ:
```go
func (p *Person) changeName(name string) {
	p.name = name
}
```

Задача с собеседования:

```go
package main

import "fmt"

type Address struct {
	city   string
	street string
	house  int
}

func (a *Address) setCity(city string) {
	a = &Address{
		city: city,
	}
}

func (a *Address) setStreet(street string) {
	a.street = street
}

func setHouse(addr *Address, house int) {
	addr = &Address{
		house: house,
	}
}

func main() {
	addr := Address{
		city:   "New York",
		street: "Broadway",
		house:  10,
	}

	addr.setCity("London")
	addr.setStreet("Piccadilly")
	setHouse(&addr, 5)

	fmt.Println(addr) // New York Piccadilly 10
}

```
1. setCity не мутирует объект, потому что в а создается уже абсолютно новый указатель, идет работа с новым объектом.
2. setStreet успешно поменяет поле, потому что берем ссылку исходного объекта и меняем поле.
3. setHouse делает то же что и setCity. В addr присваиваем новый объект.
Note:  если нет * в setStreet то мутации не будет, потому что работаем со ссылкой экземпляра структуры Address.

```go
package main

  

import "fmt"

  

func main() {

p := getSlice()

fmt.Println(p) // [1,10,3]

}

  

func changeSlice(s []int) {

s[1] = 10 // s is copy but have pointer to based arr So arr = [1,10,3]

func getSlice() []int {

s := []int{1, 2, 3} // [1,2,3] len=3, cap = 3

fmt.Println("len = ", len(s), "cap = ", cap(s)) // len=3, cap = 3

defer changeSlice(s) // executed after return

return s // exit

  

}
```

Задача на named и unnamed Return
```go
package main

  

import "fmt"

  

func main() {

a, b := named()

fmt.Println(a, b)

  

a, b = unnamed()

fmt.Println(a, b)

}

  

func named() (a, b int) {

a, b = 1, 2

  

defer func() {

a, b = 10, 20

}()

return a, b

}

  

func unnamed() (int, int) {

a, b := 1, 2

  

defer func() {

a, b = 10, 20
fmt.Println(a,b) // 10 20
}()

return a, b

}


```

Вывод:
10 20 <---  named 
1    2     <---  unnamed

Разгадка этой задачи состоит в том, когда применяется defer в функциях и к чему. defer расчитывается когда компилятор доходит до него но выполняется после return.

defer применяется на named переменные в функции. В unnamed  a,b это локальные переменные. Они меняются внутри, локально. Но из функции возвращаются 1 и 2. 
В named мы заранее объявили переменные которые хотим вернуть, поэтому defer их меняет.
