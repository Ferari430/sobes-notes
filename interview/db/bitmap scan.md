==bitmap scan - это не механизм индекса! Это механизм который принадлежит планировщику БД. Именно он оценивает искать запрос по индексу, по битовой мапе или по порядку!==


Представь, что у те есть список всех учеников в школе (это **таблица** в базе данных). Тебе нужно найти всех, кто:
1. Ходит в **футбольную секцию**.
2. И живёт на **улице Ленина**.

Если учеников много (тысячи), перебирать весь список по порядку — долго. **Bitmap Scan (Битовая карта, битовое сканирование)** ускоряет этот процесс вот как:

### По шагам:

**Шаг 1: Создание "масок" для каждого условия**
*   Ты быстро пробегаешься по списку и для каждого ученика задаёшь простой вопрос **ДА (1) или НЕТ (0)**.
*   **Маска для футбола:** `[0, 1, 0, 1, 1, 0, ...]` — где `1` — это "ходит в футбол", `0` — "не ходит".
*   **Маска для адреса:** `[1, 0, 0, 1, 1, 0, ...]` — где `1` — это "живёт на Ленина", `0` — "живёт не там".

Эти маски создаются очень быстро, потому что база данных знает, где искать нужные данные (у неё есть **индексы** — как оглавление в книге).

**Шаг 2: Наложение масок (битовая операция AND)**
*   Теперь ты накладываешь эти две маски друг на друга и смотришь, где в **обеих** масках стоит `1`.
*   Операция очень простая для компьютера:
    *   Маска футбола: `0, 1, 0, 1, 1, 0`
    *   Маска адреса:  `1, 0, 0, 1, 1, 0`
    *   **Результат (AND):**  `0, 0, 0, 1, 1, 0`

**Шаг 3: Достаём результат**
*   Теперь ты видишь, что единицы остались только на 4-й и 5-й позициях.
*   Осталось только **точечно заглянуть** в основную таблицу (на 4-ю и 5-ю запись) и взять оттуда имена этих учеников — **Иванов** и **Сидоров**.

### Простая аналогия:
Представь, что у тебя есть 100 коробок. Нужно найти коробки, где **и** красный шарик, **и** синий кубик.
*   **Обычный поиск:** Открываешь каждую коробку, смотришь оба предмета. 100 открываний.
*   **Bitmap Scan:**
    1.  Быстро прощупал все коробки — налепил **красные стикеры** на те, где есть красный шарик (не заглядывая внутрь глубоко).
    2.  Быстро прощупал снова — налепил **синие стикеры** на те, где есть синий кубик.
    3.  Нашёл коробки, где есть **оба стикера** (их всего 3-4).
    4.  **Только эти 3-4 коробки** открыл и достал всё их содержимое.

### Ключевые преимущества:
*   **Быстро для `WHERE ... AND ...`:** Идеален, когда условий несколько (`футбол И адрес`).
*   **Работает с несколькими индексами:** Может использовать разные индексы для каждого условия.
*   **Эффективен на средних селективностях:** Когда нужна не вся таблица, но и не 1-2 записи, а какая-то ощутимая часть.
*   **Дешёвые операции:** Битовые операции (`AND`, `OR`) — одни из самых быстрых для процессора.

### Главный недостаток:
Сами **битовые маски могут занимать много памяти**, если строк в таблице миллионы. Поэтому метод не всегда применим для огромных таблиц.

**Итог простыми словами:**  
**Bitmap Scan** — это умный способ найти то, что подходит под несколько условий, не копаясь во всей огромной куче данных. Он сначала **быстро помечает** подходящих кандидатов по каждому условию отдельно, а затем уже зная где находятся нужные данные, начинает последовательно читать каждую страницу но делает это один раз!  Если рассмотреть поиск по составному индексу, то после вычисления нужных строк постгрес будет читать страницу два раза - на каждый из индексов отдельно.

| Метод               | Как работает                                                 | Проблема                                         |
| ------------------- | ------------------------------------------------------------ | ------------------------------------------------ |
| **Index Scan**      | По каждому индексу отдельно → несколько проходов по таблице  | Страница 3 читается дважды (для каждого индекса) |
| **Sequential Scan** | Читаем ВСЕ страницы подряд                                   | Много лишних данных                              |
| **Bitmap Scan**     | Читаем КАЖДУЮ нужную страницу ОДИН раз в оптимальном порядке | ✅ Идеально                                       |
|                     |                                                              |                                                  |
