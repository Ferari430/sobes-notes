## 🧠 Порядок полей в составном индексе: почему это важно

В PostgreSQL при создании индекса на несколько колонок порядок имеет решающее значение. Индекс работает как **телефонная книга**: сначала сортируется по первой колонке, внутри неё — по второй и т.д.

### 🔑 Главное правило:
**Первыми ставьте колонки, по которым чаще всего ищут (равенство), потом колонки для сортировки или диапазонов.**

---

### 📚 Как индекс используется в запросах

Пусть есть индекс `(a, b, c)`.

#### ✅ Будет работать для условий:
- `WHERE a = 1`
- `WHERE a = 1 AND b = 2`
- `WHERE a = 1 AND b = 2 AND c = 3`
- `WHERE a = 1 AND b > 10` (диапазон по b)
- `WHERE a = 1 ORDER BY b` (сортировка)
- `WHERE a = 1 AND b = 2 ORDER BY c`

Индекс эффективен, пока задействован **самый левый столбец**. После первого условия на диапазон (или отсутствия условия) следующие колонки не работают.

#### ❌ Неэффективно или бесполезно:
- `WHERE b = 2` — нет a, индекс не поможет (кроме Index Skip Scan, но это редко)
- `WHERE a > 1 AND b = 2` — диапазон по a, b уже не фильтруется индексом (хотя a отсечёт)
- `ORDER BY b` — без a, сортировка не по индексу

---

### 🎯 Выбор порядка: пример

Допустим, таблица заказов: `(customer_id, created_at, status)`

**Частые запросы:**
1. `WHERE customer_id = 123 AND created_at > '2024-01-01'`
2. `WHERE customer_id = 123 ORDER BY created_at DESC`
3. `WHERE created_at > '2024-01-01'` (редко)

Оптимальный индекс: **`(customer_id, created_at)`**
- Покрывает запросы 1 и 2 идеально (customer_id сужает, created_at диапазон/сортировка)
- Запрос 3 — нечастый, можно мириться с Seq Scan или создать отдельный индекс на `created_at`

Если бы поставили `(created_at, customer_id)`, то:
- Запрос 1 использовал бы индекс только для created_at (диапазон), а customer_id фильтровался бы уже после чтения строк — менее эффективно.
- Запрос 2 (сортировка) — ок, но фильтр по customer_id не работает.

---

### 📌 Дополнительные советы

- **Для равенства и сортировки**: равенство первым, сортировка вторым.
- **Для покрывающих индексов** можно добавлять поля в `INCLUDE` — они не участвуют в поиске, но лежат в индексе (Index Only Scan).
- **Для уникальных индексов** порядок тоже важен для уникальности комбинации.

**Итог:** думайте о том, как фильтруются данные — сначала самые селективные условия равенства, потом диапазоны/сортировка. Тогда индекс будет работать на полную.
