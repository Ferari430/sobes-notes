Это одна из разновидностей индекс скана, при том очень быстрая.
Допустим мы построили индекс по id в какой то таблице.
Далее я делаю такой запрос который должен вернуть только id, но не другие поля в таблице, соответствующие этому id.

Тогда постгрес прочитает файл с индексами и заберет оттуда id, и  не будет ходить в heap (читать pages)  для чтения индекса и других полей который соответствуют этому id.

index скан работает как раз по такой схеме: сначала идем в файл с индексами, находим нужный id, берем tid (указатель на page где лежит строка с данными) и идем в page и забираем оттуда данные.

Но такой индекс зависит от visibility map в которой хранится информацию о том сколько страниц сейчас где все записи актуальны (То есть что запись не помечена как DELETED). Чтобы не нужно было обращаться к page и перечитывать данные. Таким образом если таблица обновляется очень часто, то index only скан невозможен. Потому что будет много записей с пометкой DELETED и постгресу все равно нужно будет идти и искать актульную запись.

```plaitext
visibility map отражает состояние pages. А именно, она хранит специальный бит как маску, 0 или 1. Выставляет это значение VACUUM. Именно он сканирует страницы на наличие удаленных и измененных строк.
  
  VACUUM сканирует страницу и обнаруживает, что **все строки на ней актуальны** и видны всем текущим и будущим транзакциям (нет ни удаленных, ни измененных версий) 
**Условия для выставления бита:**

1. **Нет «мертвых» строк** (не помечены как удаленные)
    
2. **Все версии строк видны** в любой момент времени
    
3. VACUUM удерживает блокировку на странице, чтобы никто не влез 
    

**Как сбрасывается:**  
Любая операция изменения данных (`INSERT`, `UPDATE`, `DELETE`) на этой странице **мгновенно сбрасывает бит обратно в 0** []

**Итог:** 1 появляется только после зачистки VACUUM и живет до первой модификации данных на странице.
  
 
```
