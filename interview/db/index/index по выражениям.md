Повесим индекс на колонку с
Таблица создавалась следующим образом:
в ней:
колонка а содержит рандомные числа до 100_000
колонка b содержит разные буквы
Колонка с содержит true/false в соотношении 1%/99%

```sql
SELECT  
    c AS "Значение в колонке b",  
    COUNT(*) AS "Количество объектов"  
FROM t  
GROUP BY c  
ORDER BY COUNT(*) DESC;
```

Если будем  делать запрос на true то индекс будет работать:
```sql
explain (analyze , costs off) SELECT * from t where c = true;
```

```text
Index Scan using t_c_idx on t (actual time=0.066..0.214 rows=1021 loops=1)
  Index Cond: (c = true)
Planning Time: 0.066 ms
Execution Time: 0.256 ms
```

Если на false:
```text
Seq Scan on t (actual time=0.054..7.217 rows=98979 loops=1)
  Filter: (NOT c)
  Rows Removed by Filter: 1021
Planning Time: 0.052 ms
Execution Time: 9.978 ms
```

То есть при высокой селективности для поиска по true ищем по индексу и имеем быстрое выполнение.
При низкой селективности имеем медленное выполнение из-за seq scan.

Такой индекс будет распределять по b-tree дереву абсолютно все значениЯ столбца с. Однако 99% столбца с значением false обходится при помощью seq scan. Индекс держит в себе лишнюю информацию. 
Поэтому можно создавать индексы на столюцы и только на те элементы которые нам необходимы:
```sql
create index on t(c) where c = true
```

Такой индекс будет занимать уже не 80 страниц а 2. Такой индекс называется индекс по выражению.

Основной смысл: не создавать индекс по полям с низкой селективностью.
