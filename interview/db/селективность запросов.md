Не все индексы одинаково хороши.
Селективность - сколько строчек вернет селект.
![Pasted image 20251214105327](../../attachments/Pasted%20image%2020251214105327.png)

- **Высокая селективность** → условие **очень «точное»**, возвращает мало строк.
    
- **Низкая селективность** → условие «широкое», возвращает много строк.

Чем меньше селективность, тем эффективнее индекс.

```text
B-Tree индекс работает лучше, когда селективность высокая, потому что:

Индекс позволяет быстро найти нужные строки, обойдя только небольшую часть дерева.

Обращения к heap минимальны (несколько random I/O), если нужны данные не покрытые индексом.

Если строк много (низкая селективность), то индекс всё равно придётся проходить почти весь диапазон, а random I/O к heap может быть дороже, чем просто Sequential Scan. Потому что random_page_cost = 4  у индексного сканирования, другими словами стоимость прочтения одной страницы при индекс скане = 4, в то время как при seq scane это значение равно единице. Хотя это значение можно менять вручную!

```


Если селективность запроса слишком большая, планировщик БД может выбрать полное сканирование таблицы вместо сканирования индекса.

Селективность индекса дает понять, эффективен ли будет индекс или нет.
Например селективность запроса по id = 1 потому что из запроса можно вытащить только одну запись в таблице.

Селективность по полу = 50% либо 1 либо 2.  ==Тут хз==
