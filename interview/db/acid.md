ACID - это некоторый набор гарантий которые предоставляет БД при работе с данными.
1. А - атомарность
		Транзация в бд - логические связные операции (insert update delete ...) которые выполняются как единое целое.
2. C - consistency
		Согласованность гарантиурет, что бд будет соблюдать все правила и ограничения.
		Например нельзя создать заказ, ссылающийся на несуществующую таблицу. Или если у пользователя есть баланс с типом, который может иметь только не отрицательные значения, то бд гарантирует что это значение будет  > 0.
3. I  - isolation
		Обеспечение concurrent safety записи в бд. Каждая транзакция видит либо состояние до или после другой транзакции в зависимости от уровня иоляции транзакций (Read Commited, Repeatable Read, Serializable)
4. D - durability (долговечность)
		После успешной вставки либо коммита все изменения становятся постоянными. Он никуда не пропадет даже если выключится свет (все таблицы хранятся в файлах).

- При ответе на букву А лучше упоминуть про ==откатываемость==. 
Представим что есть 5 запросов на создание объекта в таблице. Если обвалился второй запрос, то пришлось бы отлавливать ошибку, делать антизапрос на второй запрос, и  так же делать антизапрос для первого запроса. Этот подход плохо масштабируется, поэтому были придуманы транзакции.


- Консистентность (согласованность) - это про всякие проверки ограничений. Например:
	- CHECK
	- UNIQUE
	- NOT NULL
	- PRIMARY KEY
	- REFERENCES (foreign key)
	- ON DELETE (CASCADE, SET NULL...) ==ПРОРЕСЕРЧИТЬ==
Пример несогласованности данных: у 3 книги есть ссылка на автора с id = 4, но такого автора нет. Если бы мы прописали ограничения, то такой ситуации не случилось бы.

- Изоляция обеспечивается путем выбора уровня изоляции. [MVCC. Уровни изоляции транзакций и аномалии](mvcc/MVCC.%20Уровни%20изоляции%20транзакций%20и%20аномалии.md)

- Надежность - если транзакция закомитилась, то данные сохранились на надежный носитель. Если инстансов серверов много (используем репликацию БД) то изменения сохранятся на всех инстансах.
