## 🔹 В Go **встраивание (embedding)** ≠ наследование

| Свойство         | Наследование (OOP)                         | Встраивание Go                                                                            |
| ---------------- | ------------------------------------------ | ----------------------------------------------------------------------------------------- |
| Тип              | Подтип                                     | Нет подтипа                                                                               |
| Полиморфизм      | Да, через наследуемые методы               | Только через интерфейсы                                                                   |
| Доступ к методам | Методы базового класса доступны в дочернем | Методы встраиваемого типа **“пробрасываются”**, но тип не становится подтипом             |
| Переопределение  | Можно override                             | Можно объявить метод с тем же именем → **скрывает** метод встроенного, но **нет супер()** |

---

### Пример в Go

```go
type Animal struct{}

func (Animal) Speak() { fmt.Println("Animal sound") }

type Dog struct {
    Animal // embedding
}

func (Dog) Speak() { fmt.Println("Woof") }

func main() {
    d := Dog{}
    d.Speak()        // Woof
    d.Animal.Speak() // Animal sound
}
```

- **Dog не является подтипом Animal**, просто **встроил методы**
    
- Нет `super` или автоматического полиморфизма
    

---

### Почему так сделано

- Go **считает композицию лучше наследования**: «has-a» вместо «is-a»
    
- Простота и явность: **нет скрытых зависимостей**
    
- Полиморфизм достигается через **интерфейсы**, а не через иерархию классов
    

---

### ⚡ Идеальный ответ для собеса

> Встраивание в Go — это композиция: один тип “включает” другой и получает доступ к его методам, но **не создаёт подтип** и не даёт классического полиморфизма наследования.
